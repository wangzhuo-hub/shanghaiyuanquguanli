# 多园区大屏看板方案

版本：2026-05-16  
适用项目：金蝶招商管理看板（标准版）  
方案状态：设计确认稿，先输出方案，不改动功能代码

## 1. 建设目标

新增一个“多园区经营大屏”，用于会议室、前台电视、招商经营例会等场景，自动滚动播放多个园区的关键经营数据和最新业务动态。

大屏需要满足四个核心目标：

1. 多园区经营总览：集团层面快速看到出租率、合同应收、实收、回款完成率、欠款等核心指标。
2. 园区横向对比：不同园区之间可以比较出租情况、收款情况、预算偏差和风险水平。
3. 最新动态滚动：新签约客户、新收款、新开票、即将到期、欠款风险等事件持续滚动播放。
4. 智能预警：对快到期客户、逾期未收客户、低出租率园区、低回款率园区等进行自动提醒。

说明：用户提到“预期客户预警”，结合上下文判断应为“逾期客户预警”，即应收款逾期未收客户预警。若后续确实需要“预计签约客户/意向客户预警”，需先补充意向客户数据来源。

## 3. 大屏入口与权限

建议新增独立大屏模式，而不是把现有工作台简单放大。

### 3.1 入口设计

建议支持三种入口：

| 入口 | 用途 |
|---|---|
| 侧边栏“经营大屏” | 登录系统后手动进入 |
| `/bigscreen` | 会议室或电视固定访问 |
| `?screen=tv` | 不引入路由库时的轻量兼容入口 |

当前项目是单页应用，未看到独立路由层。初版可以使用 URL query 参数实现：

- `window.location.search.includes('screen=tv')`
- 命中后渲染 `BigScreenDashboard`
- 隐藏侧边栏、顶部普通工具栏和编辑入口

### 3.2 权限边界

| 用户角色 | 大屏可见范围 |
|---|---|
| `platform_admin` | 所有启用园区 |
| `group_admin` | 当前账号授权的所有园区 |
| `park_admin` | 当前园区 |
| `park_user` | 当前园区，只读 |

多园区范围来自：

- 当前登录用户：`AuthUser.allowedProjectIds`
- 园区目录：`fetchAuthorizedParks()` -> `pb_parks`
- 当前项目 ID：`cloudConfig.projectId`

大屏只读，不提供合同、收款、预算编辑能力。

## 4. 页面结构设计

大屏采用自动轮播，每一屏表达一个明确主题。建议默认 20 秒切换，60 秒刷新数据。

### 4.1 轮播页面

| 页面 | 内容 | 数据来源 |
|---|---|---|
| 集团总览 | 多园区汇总 KPI、大数字卡片、总体风险 | 多园区 `DashboardData` 或 `pb_kpi_snapshots` |
| 园区对比 | 出租率、实收、回款率、预算偏差排名 | `buildKpiSummaryFromProcessedData` |
| 单园区经营 | 单个园区出租、收款、应收、欠款、最新签约 | 该园区 `DashboardData` |
| 最新动态 | 新签约、新收款、新开票、到期、逾期滚动 | 合同、收款、发票、应收明细 |
| 智能预警 | 快到期、逾期未收、低出租率、低回款率 | 合同、应收明细、KPI 汇总 |

### 4.2 视觉原则

- 使用深色全屏大屏风格，区别于后台管理白底表格。
- 第一屏优先展示大数字，减少小字说明。
- 每个指标必须展示单位：万元、平方米、百分比、户。
- 金额统一用万元展示，大屏取整。
- 百分比统一取整或保留 1 位，避免过多小数。
- 风险色彩建议：
  - 正常：青色 / 绿色
  - 注意：黄色 / 橙色
  - 高风险：红色

## 5. 核心指标与数据来源

大屏指标必须复用现有计算口径，禁止在大屏组件里重新手写一套财务计算。

### 5.1 推荐计算链路

对每个园区：

1. 使用 `fetchCloudBackup(config, projectId)` 读取该园区结构化数据。
2. 合并 `generateInitialData()` 作为默认字段兜底。
3. 调用 `calculateDashboardMetricsService(rawData, { year, quarter: 'All', billingSelectedMonth })`。
4. 调用 `buildKpiSummaryFromProcessedData(processedData, year)` 得到年度 KPI。
5. 大屏事件与预警从 `processedData` 派生。

这与当前 `App.tsx` 中 `buildParkMetric()` 的管理员汇总口径一致。

### 5.2 KPI 快照的使用原则

`pb_kpi_snapshots` 可以用于大屏快速首屏加载，但不能作为唯一权威数据。

建议策略：

| 场景 | 读取策略 |
|---|---|
| 首屏快速展示 | 先读 `fetchCloudKpiSnapshot(config, year)` |
| 快照不存在 | 回退 `fetchCloudBackup` + 实时计算 |
| 需要最新动态 | 必须读取 `pb_tenants`、`pb_payments`、`pb_invoices` 或完整 `DashboardData` |
| 数据刷新 | 定时重新读取全量并重算 |

原因：KPI 快照只有年度 summary 和 monthly trends，不包含新签约列表、新收款明细、发票明细、客户到期明细，无法支撑动态滚动与智能预警。

### 5.3 指标字段映射

| 大屏指标 | 推荐来源 | 说明 |
|---|---|---|
| 园区名称 | `pb_parks.name` / `ParkInfo.name` | 无名称时回退 `projectId` |
| 总面积 | `summary.totalArea` | 来自 `buildKpiSummaryFromProcessedData` |
| 客户数 | `summary.tenantCount` | 当前统计口径客户数 |
| 出租率 | `summary.occupancyRate` | 与工作台一致 |
| 出租率目标 | `summary.annualOccupancyTarget` | 来自年度目标或默认值 |
| 年初预算 | `summary.annualInitialBudget` | 来自年度目标或月度初始化预算 |
| 实际合同应收 | `summary.annualContractReceivable` | 优先使用合同应收字段 |
| 年度实收 | `summary.annualRevenueCollected` | 来自收款与月度趋势 |
| 回款完成率 | `summary.annualGoalCompletion` | 实收 / 合同应收 |
| 预算收款 | `summary.annualBudgetTarget` | 预算表或生效方案口径 |
| 预算执行率 | `summary.annualBudgetCompletion` | 实收 / 预算收款 |
| 预算偏差 | `(合同应收 - 年初预算) / 年初预算` | 大屏自行派生即可 |
| 本月应收 | `currentMonthBilling.amountDue` 汇总 | 需按当前账期计算 |
| 本月实收 | `currentMonthBilling.amountPaid` 汇总 | 需按当前账期计算 |
| 本月未收 | `amountDue - amountPaid` 汇总 | 只统计正数 |
| 最新签约 | `processedData.recentSignings` 或 `tenants.signingDate` | 推荐扩展为近 30 / 90 天 |
| 最新收款 | `payments` 按 `date` 排序 | 只取 `status = Received` |
| 最新开票 | `invoices` 按 `invoicedAt` 排序 | 只取 `status = Invoiced` |
| 快到期客户 | `tenants.leaseEnd` | 排除退租 / 历史合同 |
| 逾期未收客户 | `currentMonthBilling.status` + 应收截止规则 | 见智能预警 |

## 6. 最新动态滚动方案

### 6.1 事件类型

建议新增前端派生类型 `BigScreenEvent`，初期不必新增数据库集合。

```ts
export type BigScreenEventType =
  | 'new_contract'
  | 'new_payment'
  | 'new_invoice'
  | 'expiring_contract'
  | 'overdue_receivable'
  | 'low_occupancy'
  | 'low_collection';

export interface BigScreenEvent {
  id: string;
  parkId: string;
  parkName: string;
  type: BigScreenEventType;
  level: 'info' | 'success' | 'warning' | 'danger';
  title: string;
  description: string;
  tenantId?: string;
  tenantName?: string;
  amount?: number;
  area?: number;
  occurredAt: string;
}
```

### 6.2 事件生成规则

| 事件 | 生成来源 | 触发规则 | 排序时间 |
|---|---|---|---|
| 新签约客户 | `tenants.signingDate` | 签约日在近 30 天内，且非退租合同 | `signingDate` |
| 新收到一笔钱 | `payments` | `status = Received` 且 `date` 在近 30 天内 | `date` |
| 新开票 | `invoices` | `status = Invoiced` 且 `invoicedAt` 在近 30 天内 | `invoicedAt` |
| 快到期合同 | `tenants.leaseEnd` | 距到期日 0-90 天，且合同仍有效 | `leaseEnd` |
| 逾期未收 | `currentMonthBilling` | 当前账期已过应收提醒日且未收 / 部分收 | 当前日期 |
| 低出租率园区 | KPI summary | `occupancyRate < annualOccupancyTarget - 5` | 当前日期 |
| 低回款率园区 | KPI summary | `annualGoalCompletion < 当前月份时间进度 - 10` | 当前日期 |

动态列表按 `occurredAt desc` 排序，取最近 50 条滚动播放。

### 6.3 滚动播放规则

建议大屏底部保留常驻滚动条：

- 每条动态显示：园区、事件标签、客户名、金额 / 面积、日期。
- 一行无法展示时使用水平滚动，不要换成多行挤压。
- 滚动速度按内容长度动态调整，保证会议室屏幕可读。
- 鼠标悬停或触摸时暂停滚动，便于查看。
- 当没有事件时展示“暂无新增动态”，不要空白。

### 6.4 推荐文案模板

| 类型 | 文案 |
|---|---|
| 新签约 | `{parkName} 新签约 {tenantName}，面积 {area}㎡，起租 {leaseStart}` |
| 新收款 | `{parkName} 收到 {tenantName} {paymentTypeLabel} {amount}万元` |
| 新开票 | `{parkName} {tenantName} 已开票 {amount}万元` |
| 快到期 | `{parkName} {tenantName} 合同将在 {daysLeft} 天后到期` |
| 逾期未收 | `{parkName} {tenantName} 逾期未收 {amount}万元` |
| 低出租率 | `{parkName} 出租率 {occupancyRate}%，低于目标 {gap} 个百分点` |
| 低回款率 | `{parkName} 回款进度 {collectionRate}%，低于时间进度` |

## 7. 智能预警方案

智能预警分为合同预警、收款预警、经营预警三类。

### 7.1 快到期客户预警

数据来源：

- `pb_tenants.lease_end`
- `pb_tenants.status`
- `pb_tenants.total_area`
- `pb_tenants.monthly_rent`

前端对象：

- `Tenant.leaseEnd`
- `Tenant.status`
- `Tenant.totalArea`
- `Tenant.monthlyRent`

触发规则：

| 等级 | 条件 |
|---|---|
| 高 | 0-30 天内到期 |
| 中 | 31-60 天内到期 |
| 低 | 61-90 天内到期 |

过滤规则：

- 排除 `ContractStatus.Terminated`
- 排除 `ContractStatus.Expired`
- 对 `Pending` 合同不做快到期预警

输出字段：

- 客户名称
- 园区
- 到期日
- 剩余天数
- 租赁面积
- 月租金
- 风险等级

### 7.2 逾期未收客户预警

数据来源：

- `pb_payments`
- `pb_tenants`
- `pb_billing_period_notes`
- `services/dashboardMetrics.ts` 计算出的 `currentMonthBilling`

前端对象：

- `BillingDetail.amountDue`
- `BillingDetail.amountPaid`
- `BillingDetail.status`
- `BillingDetail.deferredToPeriod`
- `BillingDetail.deferredFromPeriod`
- `BillingDetail.billingTermsTenant`

触发规则：

1. 对当前选择账期生成 `currentMonthBilling`。
2. 计算 `unpaidAmount = amountDue - amountPaid`。
3. 当 `unpaidAmount > 0` 且账期已过提醒日，生成预警。

建议提醒日：

- 默认：账期月份最后一天。
- 如后续需要更精确，可根据合同 `firstPaymentDate`、`paymentCycle`、`paymentTerms` 计算应收日。
- 对已缓缴的应收，若存在 `deferredToPeriod`，不在原账期重复标高危，而是在缓缴目标账期提醒。

预警等级：

| 等级 | 条件 |
|---|---|
| 高 | 未收金额 >= 10 万元，或逾期超过 30 天 |
| 中 | 未收金额 3-10 万元，或逾期 8-30 天 |
| 低 | 未收金额小于 3 万元，或逾期 1-7 天 |

注意：不要直接用 `PaymentRecord.period` 手写匹配规则。应收与核销口径已经在 `services/dashboardMetrics.ts`、`services/receivableListHelpers.ts` 中处理，必须复用 `currentMonthBilling` 或 `buildBillingDetailsForPeriodService()`。

### 7.3 低出租率预警

数据来源：

- `summary.occupancyRate`
- `summary.annualOccupancyTarget`

触发规则：

| 等级 | 条件 |
|---|---|
| 高 | 低于目标 10 个百分点以上 |
| 中 | 低于目标 5-10 个百分点 |
| 低 | 低于目标 0-5 个百分点 |

### 7.4 低回款率预警

数据来源：

- `summary.annualGoalCompletion`
- 当前日期对应的年度时间进度

建议规则：

```ts
timeProgress = 当前月份 / 12 * 100
gap = timeProgress - annualGoalCompletion
```

| 等级 | 条件 |
|---|---|
| 高 | 回款率落后时间进度 20 个百分点以上 |
| 中 | 落后 10-20 个百分点 |
| 低 | 落后 5-10 个百分点 |

示例：2026 年 5 月，时间进度约 41.7%。若某园区回款完成率 25%，落后 16.7 个百分点，触发中风险。

### 7.5 大额欠款预警

数据来源：

- `currentMonthBilling`
- `MonthlyInitData.accumulatedArrears`

建议规则：

- 单客户当前未收金额超过 10 万元：高风险
- 园区累计欠款超过年度合同应收 5%：中风险
- 园区累计欠款超过年度合同应收 10%：高风险

## 8. 数据刷新与实时性

### 8.1 初版刷新策略

不引入复杂实时订阅，先保证稳定。

- 大屏每 60 秒刷新一次所有授权园区数据。
- 每 20 秒切换一屏。
- 每 6 秒切换一次最新动态高亮项。
- 页面顶部显示“数据更新时间”。

### 8.2 进阶刷新策略

后续可引入 PocketBase Realtime：

- 订阅 `pb_tenants`
- 订阅 `pb_payments`
- 订阅 `pb_invoices`
- 订阅 `pb_billing_period_notes`

收到变更后：

1. 标记对应园区为 dirty。
2. 防抖 2-5 秒重新拉取该园区全量。
3. 重新计算 KPI、动态、预警。

### 8.3 最新动态准确性

大屏的“最新”不应该只依赖 KPI 快照，因为快照不含明细事件。

准确实现必须至少读取以下对象：

- 合同：用于新签约和到期预警
- 收款：用于新收款动态
- 发票：用于新开票动态
- 应收明细：用于逾期未收预警

## 11. 实施步骤

### 阶段一：方案落地与静态大屏

目标：能打开大屏，展示多园区汇总与轮播页面。

任务：

1. 新增 `BigScreenDashboard.tsx`。

## 12. 准确性校验清单

实现时必须逐项校验：

| 校验项 | 标准 |
|---|---|
| 出租率 | 与当前工作台同年度展示一致 |
| 年度实收 | 与当前工作台预算执行合计一致 |
| 合同应收 | 与工作台“实际合同应收”口径一致 |
| 回款完成率 | 与管理员“所有园区经营汇总”一致 |
| 新签约 | 与 `RecentActivityTable` 的近期签约来源一致，允许扩大窗口 |
| 新收款 | 只统计 `status = Received` |
| 开票动态 | 只统计 `status = Invoiced` |
| 快到期 | 排除已退租、已到期历史合同 |
| 逾期未收 | 使用 `currentMonthBilling`，不要绕开核销规则 |
| 多园区权限 | 只能访问 `allowedProjectIds` 内园区 |

## 13. 风险与处理

### 13.1 KPI 快照过期

风险：`pb_kpi_snapshots` 可能不是最新。

处理：

- 大屏首屏可用快照。
- 后台立即拉全量并重算。
- 重算完成后替换展示数据。
- 显示 `refreshedAt` 和 `latestUpdatedAt`。

### 13.2 多园区拉取耗时

风险：园区多时逐个 `fetchCloudBackup` 可能慢。

处理：

- 初版可串行，避免打爆 PocketBase。
- 后续改为并发池，最多同时 3 个园区。
- 首屏先展示 KPI 快照。

### 13.3 逾期规则口径复杂

风险：合同付款周期、缓缴、手工应收、特殊业态会影响应收。

处理：

- 逾期预警以 `currentMonthBilling` 为准。
- 不直接按合同月租和收款表自行相减。
- 缓缴记录尊重 `deferredToPeriod`。

### 13.4 电视端长期播放稳定性

风险：动画和定时器导致内存增长。

处理：

- 所有 `setInterval` 在组件卸载时清理。
- 滚动动画优先 CSS。
- 每次刷新只替换必要 state。
- 数据失败时不清空旧数据。

## 14. 推荐先做的最小可用版本

建议第一版范围如下：

1. 新增大屏入口：`?screen=tv`。
2. 支持集团总览、园区对比、单园区轮播、最新动态。
3. 数据每 60 秒刷新。
4. 页面每 20 秒轮播。
5. 最新动态来自近 30 天合同、收款、发票。
6. 预警先做快到期客户和逾期未收客户。
7. 经营预警先做低出租率和低回款率。

这版不新增 PocketBase 集合，不改变现有保存逻辑，风险最小，能快速上线验证展示效果。

## 15. 后续增强

后续可考虑：

- 新增 `pb_bigscreen_configs`：保存轮播间隔、隐藏金额、展示园区等配置。
- 新增 `pb_bigscreen_events`：将事件固化为流水，保留历史展示记录。
- 接入 PocketBase Realtime：新签约、新收款后自动刷新。
- 增加“招商目标达成预测”：根据当前签约节奏预测全年出租率。
- 增加“现金流预测”：根据账期和合同周期预测未来 3 个月应收。
- 增加“风险客户画像”：结合欠款、即将到期、历史变更记录生成客户风险分。

## 16. 结论

本项目适合采用“现有结构化数据 + 现有指标计算 + 新增大屏展示层”的方案。

推荐不要另建一套大屏数据计算逻辑，也不建议初版新增复杂事件表。最稳妥的路径是：

1. 读取 `pb_*` 权威数据。
2. 复用 `dashboardMetrics` 统一计算 KPI。
3. 从合同、收款、发票、应收明细派生最新动态和智能预警。
4. 用独立大屏组件负责展示、轮播和刷新。

这样既能保证数据调用准确，又能快速实现滚动播放最新动态和智能预警。
