# 移动端与字段口径上线验收清单

> 适用范围：移动端内容与管理优化、关注字段、自定义字段偏好、历史欠费筛选、楼宇轻管理、预算轻编辑，以及对应的阿里云 / Docker 部署验收。
> 更新日期：2026-06-24

本文档把《UI 界面内容与移动端使用优化建议》和《UI 毛玻璃设计优化建议》里分散的落地项收束为上线门槛。目标不是替代功能测试，而是在部署前明确：哪些字段从哪里算、哪些接口必须可用、哪些迁移必须先跑、哪些视口必须截图复核。

每次实际上线前，应运行 `npm run qa:rollout:record -- --env 阿里云生产` 生成验收记录，或复制 [11-移动端与字段口径上线验收记录模板.md](./11-移动端与字段口径上线验收记录模板.md) 留存记录，尤其是截图 QA、封账 dry-run、云端接口、灰度账号和最终结论。可先用 `npm run qa:mobile-auth-state -- --url http://127.0.0.1:5173/` 通过 QA 账号手动登录并保存本机登录态，再用 `npm run qa:mobile-screenshots -- --url http://127.0.0.1:5173/ --color-scheme both --reduced-motion both --storage-state output/mobile-auth-state/auth-state.json --require-authenticated` 批量生成五个基础视口的登录后浅色 / 深色、默认动态 / 减少动态截图，并在登录态过期或仍停留登录页时直接失败。随后用 `npm run qa:mobile-screenshot-report -- output/mobile-screenshot-qa/截图目录/README.md` 校验报告内容确实覆盖登录态、`requireAuthenticated=true`、登录后壳 selector、浅色+深色、默认+减少动态和五个视口，再人工补充更多入口、筛选 sheet、月度明细、预算编辑和楼宇 action sheet 等状态截图。记录补齐后运行 `npm run qa:rollout:record:check -- docs/rollout-records/记录文件.md` 检查关键占位项是否清完；该命令也会复核记录中填写的截图报告内容。`npm run qa:rollout` 只能证明本地可自动验证项通过，不能替代人工截图和生产环境接口验收。

## 1. 上线结论门槛

上线前必须同时满足以下条件：

- `npm run qa:rollout` 通过，作为部署前一键回归入口。
- `npm run qa:mobile-ui` 通过，作为移动 UI 源码守卫的第一道闸口。
- `npx tsc --noEmit` 通过，确认本轮组件拆分、接口类型和服务调用没有类型漂移。
- `npm run build` 通过，确认生产构建和懒加载模块可被 Vite 正确打包。
- 关键服务测试通过，至少覆盖关注字段、历史欠费、预算移动调整、导入预算快照、主经营指标口径和验收记录脚本。
- 使用 375x812、390x844、430x932、768x1024、1024x768 视口做移动 / 平板截图 QA。
- `npm run qa:mobile-auth-state -- --url http://127.0.0.1:5173/` 已用 QA 账号生成本机登录态文件；该文件不得提交。
- `npm run qa:mobile-screenshots -- --url http://127.0.0.1:5173/ --color-scheme both --reduced-motion both --storage-state output/mobile-auth-state/auth-state.json --require-authenticated` 已输出基础视口登录后浅色 / 深色、默认动态 / 减少动态截图，截图路径已填写到上线验收记录。
- `npm run qa:mobile-screenshot-report -- output/mobile-screenshot-qa/截图目录/README.md` 通过，确认截图报告不是登录页、未启用登录后壳校验、单一深色 / 浅色截图或缺少减少动态效果证据。
- 历史欠费筛选上线前完成封账明细 dry-run 检查，缺 `details_json` 的旧封账月不得跳过。
- 阿里云或 Docker 环境已应用 PocketBase migrations，包含 `pb_user_preferences` 用户偏好集合。
- 已按上线验收记录模板填写自动回归、截图 QA、封账迁移、云端接口和灰度观察结果。
- `npm run qa:rollout:record:check -- docs/rollout-records/记录文件.md` 通过，确认关键占位项已经清理。

## 2. 字段口径验收

| 字段 / 能力 | 权威计算来源 | 上线验收点 |
|---|---|---|
| 年度收款达成 | `DashboardData.annualRevenueCollected`、`resolveAnnualInitialBudget`、`monthlyTrends.revenueCollected` | 工作台主 KPI、月度收款明细和年度目标卡保持同源；当前园区有数据时不得只显示 `...` 或 `读取中` |
| 月度合同应收 | `services/dashboardMetrics.ts` 的 `monthlyTrends.contractReceivable` | 工作台月度明细、财务应收核销和预算应收预览不得各自重算；导入预算格为 0 时不得抹掉合同滚动应收 |
| 实际收款 | `monthlyTrends.revenueCollected` 与收款记录归属月 | 初始化历史实收只能在无收款记录时兜底；不能被导入预算表覆盖 |
| 出租率 / 已租面积 | `services/parkAreaMetrics.ts` 和 `DashboardData.occupancyRate` | 楼宇管理、工作台辅助字段和大屏面积指标使用同一面积口径；自用和特殊业态规则按服务层保持 |
| 累计欠款 | `DashboardData.accumulatedArrears` 与 `currentMonthBilling` | 园区级累计欠款只用于园区展示，不得反推客户级历史欠费 |
| 客户级历史欠费 | `services/tenantHistoricalArrears.ts` 的 `buildTenantHistoricalArrears` | 从 2026-01 到当前自然月上月；封账月必须读取 `SealedMonth.billingDetails`；缺明细时筛选应禁用并说明原因 |
| 自定义关注字段 | `services/dashboardCustomFields.ts` | 候选字段、默认字段、最多 5 个、字段 resolver 和本地 fallback 都由服务层控制；UI 组件不得新增字段计算 |
| 关注字段跨设备偏好 | `pb_user_preferences.user_id + preference_key` | 本地即时保存和云端同步都可用；状态文案包含读取、同步中、已同步到账号、本机已保存 |
| 预算移动轻编辑 | `services/budgetMobileAdjustment.ts` 与 `services/budgetTableImport.ts` | 非导入年份走 `amount_delta`；导入预算表年份只更新导入快照并重算行 / 月 / 年合计 |
| 楼宇移动快速 / 批量状态处理 | `BuildingManager` 的资产台账更新链路 | 只允许非合同控制房源切换待租 / 预留 / 自用；不修改合同、租户引用、面积统计和导入历史 |

## 3. 接口与迁移验收

必须在部署环境确认以下接口或迁移存在：

- `GET /api/integration/app/preferences/dashboard-custom-fields`
- `PUT /api/integration/app/preferences/dashboard-custom-fields`
- `POST /api/integration/app/compute/tenant-historical-arrears`
- `pocketbase/pb_migrations/1789000000_created_pb_user_preferences.js`

云端偏好接口验收：

- 未登录或 token 无效时不能写入他人偏好。
- 同一用户同一 `preference_key` 只保留一条有效偏好。
- 云端失败时界面保持当前本地选择，并显示本机兜底状态。

历史欠费接口验收：

- 移动查询进入历史欠费筛选后，优先走云端接口。
- 网关不可用、服务端计算关闭、token 缺失、本地存在未保存编辑时才走前端按需 fallback。
- 物业账号只返回其权限内的物业费欠费，不应返回租金欠费。

## 4. 旧封账明细迁移

历史欠费筛选上线前，先执行 dry-run：

```bash
npm run seal:backfill -- --from 2026-01 --to 上月 --dry-run
```

验收标准：

- 已存在且有 `details_json` 的封账月应跳过。
- 已存在但缺 `details_json` 的封账月应被识别为 `update_for_missing_details`。
- 缺失封账月是否创建，应按当次上线范围确认；只修复旧明细时使用 `--missing-details-only`。
- 未完成明细补齐前，客户级历史欠费筛选不得作为正式可用能力开放。

## 5. 移动与平板截图 QA

至少复核以下视口：

| 视口 | 重点页面 | 必看问题 |
|---|---|---|
| 375x812 | 工作台、客户查询、月度明细 | 底部导航是否遮挡关注字段、待办卡或园区切换；关注字段避让必须包含 safe-area |
| 390x844 | 工作台、更多入口、筛选 sheet | 顶部上下文、按钮触控、筛选数量是否清楚 |
| 430x932 | 工作台、楼宇资管、预算明细 | 关注字段不得被底部导航覆盖；action sheet、预算编辑浮层是否可读且可关闭 |
| 768x1024 | 合同、财务、发票、预算 | 平板主从预览是否出现，右侧预览是否被筛选同步重置 |
| 1024x768 | 横屏平板 / 小桌面 | 1024px 边界下桌面宽表与移动导航是否切换正确 |

截图 QA 通过标准：

- 无横向溢出、遮挡、半透明文字读不清、固定底栏压字。
- 核心移动卡片标签不低于 12px，主数值和关键金额在玻璃背景上有足够对比。
- iPhone 深色外观下，登录 / 注册页、工作台浅色 readable 玻璃卡片、今日待办、关注字段和底部导航不得出现白字叠白底、输入框占位过浅或辅助文字发白。
- 系统高对比或降低透明度下，登录 / 注册页、工作台主 KPI、关注字段、月度明细和底部导航必须退到近不透明内容层，不能继续依赖强透明玻璃承载关键文字。
- 移动首页首屏必须避免白字叠高透明蓝色玻璃；园区标题、缓存状态、年度达成、收款进度、三列 KPI、今日待办、关注字段和底部导航都必须保持深色正文或明确蓝色强调，且与 PC 端核心信息顺序一致。
- 移动关注字段底栏避让必须同时覆盖 `safe-area` 和 `100dvh` 动态视口留白；375/390 小屏和 430×932 大屏手机都不得让字段标题或字段卡被固定底部导航覆盖。
- 系统减少动态效果下，工作台、bottom sheet、月度明细、楼宇 action sheet 和加载状态不得依赖滑入、缩放、淡入或旋转表达状态。
- 系统减少动态或动画中断时，工作台待办卡、关注字段卡和轻管理卡从入场动画第一帧起就必须可读，不得停在 `opacity: 0` 或偏移初始帧。
- 登录 / 注册输入框和园区多选项的实际命中区不得小于 44px，键盘 Tab 聚焦时必须有清楚的蓝色焦点环。
- 登录 / 注册字段必须有明确标签关联；邮箱键盘应使用 email 模式并关闭自动大写 / 拼写检查，密码完成键应能表达登录或完成意图。
- 登录 / 注册表单必须通过可见标题和说明建立 `aria-labelledby` / `aria-describedby` 关系。
- 登录 / 注册分段控件必须有明确分组标签，当前模式必须通过 `aria-pressed` 与视觉高亮同步。
- 登录错误、注册失败和注册成功提示必须能被辅助技术播报；提交按钮在处理中必须暴露 `aria-busy`。
- 注册申请园区多选必须有明确分组标签，加载 / 空态和已选数量变化必须可播报，园区编号不得只作为视觉小字存在。
- 移动底部导航必须有明确导航名称；更多管理弹层必须关联当前园区和年份上下文，避免只靠视觉小字表达范围。
- 客户查询筛选项必须按状态、楼栋、到期月份、收款记录、当前账期和历史欠费建立命名分组；筛选触发按钮应能表达已启用高级筛选数量。
- 打开 bottom sheet、筛选面板、轻管理 action sheet 或关注字段设置的按钮必须声明 `aria-expanded` 和 `aria-controls`，并指向稳定面板 id；空状态添加入口和常规设置入口应指向同一个设置面板。
- bottom sheet、设置弹层、月度明细和楼宇 action sheet 都有可见标题、关闭按钮、背景点击和 Escape 退出；关注字段设置必须说明最多 5 个字段、字段按钮暴露选中状态、已选数量可播报；月度明细还必须关联可见口径说明，明确年初预算、合同应收与实际收款按工作台口径汇总，并在打开后将焦点移入弹层、Tab 圈定在弹层内、关闭后返回触发入口。
- 横滑 chips、月份轨道、关注字段轨道和楼宇切换有边缘淡出或明确可滑动提示；关注字段轨道还应有列表语义和“横向滚动”说明。

## 6. 回归命令

推荐上线前直接运行：

```bash
npm run qa:rollout:record -- --env 阿里云生产
npm run qa:rollout
npm run qa:mobile-screenshot-report -- output/mobile-screenshot-qa/截图目录/README.md
npm run qa:rollout:record:check -- docs/rollout-records/记录文件.md
```

第一条命令会在 `docs/rollout-records/` 生成当次验收记录草稿；第二条命令会依次执行移动 UI 守卫、关键字段 / 移动回归测试、TypeScript 检查和生产构建；第三条命令用于在记录补齐后检查关键占位选择是否仍未填写。`npm run qa:rollout` 等价展开如下：

```bash
npm run qa:mobile-ui
npx vitest run \
  services/__tests__/dashboardCustomFields.test.ts \
  services/__tests__/dashboardCustomFieldCloudPreferences.test.ts \
  services/__tests__/tenantHistoricalArrears.test.ts \
  services/__tests__/cloudTenantHistoricalArrears.test.ts \
  services/__tests__/budgetMobileAdjustment.test.ts \
  services/__tests__/budgetTableImport.test.ts \
  services/__tests__/dashboardMetrics.test.ts \
  services/__tests__/parkAreaMetrics.test.ts \
  components/__tests__/MobileNavigation.test.tsx \
  components/__tests__/MobileTenantSearchPanel.test.tsx \
  components/__tests__/DashboardCustomFields.test.tsx \
  components/__tests__/BuildingMobileActionSheets.test.tsx
npx tsc --noEmit
npm run build
```

如果只改文档或守卫，可至少运行 `npm run qa:mobile-ui`；如果改动了字段 resolver、历史欠费、预算、楼宇或云端偏好，必须运行对应 Vitest 和类型检查。

## 7. 阿里云部署前检查

- 确认 `.env` / 云端环境变量包含正确的 PocketBase、集成网关和 AI 代理配置。
- 确认 Docker 或服务编排已经部署前端、PocketBase 和集成网关。
- 确认 `pb_data` 已备份，且 migrations 会在新版本启动时执行。
- 确认 `pb_user_preferences` 集合已创建，规则限制到当前登录用户。
- 确认 `/api/integration/app/*` 路由没有被 Nginx 或网关路径重写遗漏。
- 灰度期间优先开放一个园区或少量账号，重点观察：移动端性能、历史欠费接口耗时、关注字段云端同步、楼宇状态保存提示。

## 8. 不允许的上线捷径

- 不允许用 UI 文案或样式替代字段计算修复。
- 不允许在组件里新写欠费、应收、出租率、合同应收或预算合计公式。
- 不允许跳过封账明细迁移后仍开放客户级历史欠费筛选。
- 不允许只看桌面宽屏通过就认为移动端通过。
- 不允许只跑源码守卫而不做关键视口截图 QA。
