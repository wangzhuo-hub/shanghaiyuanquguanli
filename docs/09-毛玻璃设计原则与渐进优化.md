# 毛玻璃设计原则与渐进优化

本文档记录招商管理系统后续 UI 统一的设计原则、落地方式和验收口径。目标是让系统逐步靠近 iOS / macOS 当前的透明毛玻璃质感，同时保持企业经营数据的可读性、可靠性和移动端效率。

## 设计目标

- 视觉上轻、透、安静，避免传统后台的大面积纯白卡片和重阴影。
- 数据上清楚、稳定，关键数字不被透明背景、过度模糊或装饰层影响。
- 交互上像系统控件，有轻微 hover、press、focus 反馈，而不是只换颜色。
- 移动端优先保证任务效率：查看关键指标、搜索客户、合同录入、收款核销都要可单手完成。
- 每次视觉改造不得改变业务字段的计算口径，涉及指标展示时必须同时核对来源和测试。

项目当前的玻璃样式集中在 `index.css`，后续新增界面优先复用这些层级。

| AI Recognition | `liquid-ai-*` | AI 合同识别、AI 收款识别的输入 tab、上传落点、预览移除按钮、错误提示、匹配选择框和房号 chip | 识别弹窗允许更强的操作感，但不使用硬白上传框、硬红按钮或大块纯蓝选中态；高置信匹配用 cyan，低置信用 amber，未匹配用 rose |

### 设计令牌

- 全局背景和基础玻璃材质从 `.ios-liquid-app` 的语义变量读取：`--liquid-app-bg-*`、`--liquid-material-border`、`--liquid-material-fill`、`--liquid-material-sheen`、`--liquid-material-shadow`、`--liquid-material-highlight`、`--liquid-material-edge-*`。
- 新增全局玻璃类时优先复用这些令牌，不再直接复制大段 `rgba(255,255,255,...)`、边缘高光和阴影字面量。
- 模块级业务状态可以继续保留专属变量或局部色值，但必须说明语义，例如风险、待处理、已完成、预测、禁用。
- 暗色模式先扩展令牌，再逐层替换组件；不得直接用一组深色覆盖所有文字和背景，避免经营数据对比度失控。
- `prefers-color-scheme: dark` 已作为系统级基础兜底接入，仅覆盖全局材质、readable 内容层、常见 slate 文本和少量浅色边框 / 白底工具类；后续模块暗色必须继续做截图 QA。

## 颜色与状态

- 主色使用矿物蓝 / 冰蓝体系：`#2563eb`、`#1d4ed8`、`#0891b2`。
- 不再使用绿色作为主色。绿色只保留为明确的业务成功状态，且不能支配页面。
- 多园区大屏允许使用深色 glass 环境，但强调色仍使用 sky / cyan；在线、排行、完成率达标等状态不再用绿色作为主视觉。
- 风险、欠款、待处理用琥珀或玫红；普通中性数据用 slate。
- 分析图表的正向经营系列使用蓝 / 青，不使用绿色作为默认实收、新签或增长色；退租、风险和负向变化继续使用玫红。
- 避免一屏内出现大面积紫色、深蓝、绿色或渐变堆叠。强色只给主行动和当前选中项。
- 选中态优先使用轻量玻璃蓝，不使用大块黑底，除非是表格合计行这类强结构。
- 工作台辅助表格的完成率、累计达成和年度达成使用蓝 / 青胶囊，不用绿色作为达标主视觉。
- 冲突处理类弹窗中，本地值使用青色、服务端值使用蓝色、跳过使用 slate；不得把“用我的值”表现为绿色成功态。
- AI 识别类弹窗中，高置信匹配、已匹配数量和全部已匹配提示使用青色；未匹配和低置信继续使用玫红 / 琥珀。
- 分析页里的稳定、达标、正向经营状态使用蓝 / 青，绿色不作为稳定指数或正向排名的默认颜色。
- 共享选择器、客户洞察等跨模块组件的主题 API 与图标色只保留 blue / cyan 语义，不再使用 emerald / indigo / purple 作为内部主题名。
- 主界面、移动端工作台和自定义关注字段的 tone API 只保留 blue / cyan / sky / amber / rose / slate 语义；正向经营字段使用 blue / cyan，不再保留 emerald / violet 旧命名。
- 合同编辑、合同卡片和账单预览中的物业费、付款转移、金额调整等正向或中性经营信息使用 cyan / blue；不再使用 teal / indigo / purple 作为内部 tone 或主要文字色。
- 合同编辑器里的输入框、下拉框、日期框和文本域统一使用 readable glass field；移动端合同列表使用独立玻璃卡片和圆形状态胶囊，不再依赖硬分割线表达层级。

## 文字与数据可读性

- 关键 KPI 的数字必须使用高对比文本：`text-slate-950`、`text-blue-700`、`text-orange-600` 等。
- 表格、明细、输入区域不使用低透明背景，行 hover 需要给出可见但克制的底色。
- 弹窗中的表头、首列、合计行要有稳定背景，避免与背后的页面内容混在一起。
- 字号不随 viewport 线性缩放；移动端通过布局重排而不是无限缩小文字。
- 移动端浅色 readable 玻璃层必须保持深色正文；即使系统处于深色外观，也不得把白色卡片、待办卡、关注字段和底部导航上的 `text-slate-*` 全局改成浅字。
- 移动首屏承载正文、KPI 辅助值、待办、关注字段和轻管理列表时必须优先使用高不透明白色 readable 层（如 `--liquid-mobile-readable-fill`）；蓝色只用于主数字、进度条、选中态和状态强调，不得再用大面积蓝色 / 高透明玻璃直接承载正文。
- 系统开启更高对比度时，承载 KPI、表格、关注字段、待办和弹层正文的玻璃必须退到近不透明 readable 层；透明材质只能保留在导航 / 控件边缘，不得让白字或弱化文字直接压在高透明背景上。
- 所有按钮、卡片和胶囊文字不得溢出容器；必要时使用 `truncate`、换行或固定宽度。

## 交互与无障碍

- 可点击控件使用 `liquid-pressable`，提供 hover、active 和 focus-visible 反馈。
- 键盘焦点必须可见，尤其是年份切换、关闭按钮、导航项、保存按钮。
- 已加入 `prefers-reduced-motion` 和 `prefers-reduced-transparency` 兜底。新增玻璃类时必须兼容这两个偏好。
- 已加入 `prefers-contrast: more` 兜底。新增移动主 KPI、关注字段、明细表格、筛选 chip 或轻管理卡片时，必须同步纳入高对比内容层。
- 降低透明度偏好优先保障信息读取：新增移动主 KPI、待办、关注字段、明细表格、筛选 chip 或轻管理卡片时，必须同步纳入 `prefers-reduced-transparency: reduce`，取消实时模糊并使用更实背景。
- 减少动态效果偏好优先保障稳定感：新增移动卡片、bottom sheet、toast、加载图标、抽屉或管理弹层时，必须同步纳入 `prefers-reduced-motion: reduce`，不得依赖滑入、缩放、淡入、旋转、跑马灯或 pulse 表达状态。
- 侧栏默认窄栏，hover / focus-within 时展开；移动端侧栏必须 fixed，不得占用主内容布局宽度。
- 页面必须保留 `viewport-fit=cover`，否则 iPhone 安全区变量不会生效；所有固定底栏、底部浮层和弹窗底部操作必须继续使用 `env(safe-area-inset-bottom)`。
- 所有 `liquid-pressable` / `mobile-pressable` / 玻璃控件必须有可见 `:focus-visible` 焦点环，键盘用户不能只看到 hover / active 状态。
- 移动端全屏高度优先使用 `100dvh`，保留 `100vh` 作为旧浏览器回退，避免动态地址栏遮挡底部导航或弹窗操作区。
- 移动端禁用系统默认 tap highlight，由统一的 active 缩放和焦点环提供反馈。
- 弹窗、抽屉和长列表滚动容器使用 `overscroll-behavior: contain`，避免内部滚动带动页面或触发系统回弹误操作。

## 移动端规则

- 移动端第一屏必须直接展示当前任务，不做介绍页。
- 工作台、合同、收款入口使用 `liquid-mobile-card` 和 `liquid-mobile-hero` 作为统一入口质感。
- 移动端顶部操作区只保留高频动作；次要动作下沉到卡片、列表或弹窗。
- 搜索框、分段筛选、月份切换、关闭按钮、底部导航和列表行动按钮需要有足够触控面积，移动端目标高度不低于 44px。
- 移动端新增 `liquid-pressable` / `mobile-pressable` / chip / 图标按钮 / 可点击 label / summary 时，实际命中区必须不小于 44px；视觉上可以做轻，但不能牺牲手指命中区。
- 移动端全局 toast 要避开底部导航和安全区，默认悬浮在底栏上方，不遮挡合同、核销、查询等高频入口。
- 移动端不使用桌面大面板，不嵌套多层卡片；列表项使用清晰白底或 readable 玻璃层。
- 移动端工作台遵循“一个主 KPI + 少量固定字段 + 可配置关注字段”的层级：年度收款达成是第一焦点，出租率、累计欠款、客户数为固定辅助字段，用户自定义字段最多 5 个并采用横向滑动展示。
- 移动端顶部导航只保留页面标题、当前园区和必要账号动作；保存、AI 助手、园区完整切换等低频操作不得挤占第一屏主任务。
- 移动端月度明细、合同摘要、导入结果等密集表格默认使用逐条卡片；桌面端可继续保留宽表，但手机端不得依赖横向滚动才能读到核心值。
- 自定义字段、月度明细和移动端工作台只复用服务层已定义 resolver 或汇总结果，不允许为移动端新增第二套计算口径。
- 移动端自定义关注字段可继续使用横滑紧凑卡片，但每张卡必须暴露由字段名、resolver 数值和辅助说明组成的完整 `aria-label/title`；视觉 `truncate` 只能收敛版面，不能让字段含义只剩半截文本。
- 移动端登录 / 注册入口、初始化数据、共享客户选择器、楼宇轻管理、合同卡片、合同概要弹层、历史退租卡、预算卡、财务收款 / 应收卡、发票排期卡、物业费 / 预测 / 业务状态胶囊不得用 10px / 11px 承载关键状态；桌面宽屏可通过 `lg:text-[10px]` / `md:text-[10px]` 保留密集视图，但手机和平板必须优先 `text-xs` 以上字号。
- JS 移动导航断点使用 `MOBILE_NAV_MEDIA_QUERY = (max-width: 1023px)`；CSS 对 641–1023px 需要提供平板 / 横屏手机过渡规则，避免 JS 已进入移动导航但 CSS 仍是桌面间距。
- 移动端玻璃模糊半径控制在 18px 以内，内容卡片优先 readable / 类纸面，减少玻璃叠玻璃带来的可读性和性能压力。
- 移动端固定底栏、bottom sheet、明细弹层、抽屉和遮罩需要启用低半径 blur 与绘制隔离；复杂弹层优先 `contain: paint`，避免背景实时重绘拖慢滚动和打开/关闭动画。

## 字段计算口径保护

视觉改造不得改变以下显示字段来源：

| 字段 | 当前口径 |
| --- | --- |
| 年度收款达成 | `annualRevenueCollected / annualGoal`；`annualGoal` 优先取 `resolveAnnualInitialBudget(yearlyTargets, initializationData, selectedYear, projectId)`，再回落到 `annualRevenueTarget`、`monthlyRevenueTarget` |
| 已收 / 目标 | 已收取 `annualRevenueCollected`；目标同上 |
| 出租率 | 取工作台聚合后的 `occupancyRate` |
| 累计欠款 | 取 `accumulatedArrears` |
| 合同到期 | 取 `expiringSoon.length` |
| 本年累计出租 | 按本年 `leaseStart` 起租合同清单实时汇总面积和合同数 |
| 累计退租 | 按本年 `terminationDate`（回落 `leaseEnd`）且 `status === Terminated` 的合同清单汇总面积和合同数 |
| 提前退租 | 本年退租且 `terminationType === 'Early'` 的合同数和面积 |
| 本年新签 | 使用 `listNewSigningsInYear`，按 `signingDate`（回落 `leaseStart`）并排除已退租/已到期、续签草稿、未来待起租等不计入项 |
| 净增面积 | 本年起租面积减本年退租面积，避免混用月度新签计数 |
| 在租客户 | `status === Active` 的客户数，面积优先取 `leasedArea` |
| 空置面积 | `vacantArea`，回落到 `totalArea - leasedArea` |
| 年度合同应收 | 优先汇总 `monthlyTrends.contractReceivable`（无值时回落 `revenueTarget`），再回落到 `annualContractReceivable`、年度/月度目标 |
| 物业费实收 | `annualManagementFeeCollected`；辅助信息取 `annualManagementFeeContractReceivable` |
| 收款缺口 | `max(0, annualGoal - annualRevenueCollected)`；`annualGoal` 优先级同年度收款达成 |
| 主界面自定义关注字段 | 字段候选、默认值、最多 5 个限制和保存 key 由 `services/dashboardCustomFields.ts` 统一管理；用户保存只影响本地显示偏好，字段值仍由各 `resolve` 函数计算 |
| 多园区大屏年度租金实收 | 园区页取 `BigScreenParkMetric.annualRevenueCollected`；总览页由 `computeTotals` 对各园区实收求和 |
| 多园区大屏年度合同应收 | 园区页取 `summary.annualContractReceivable || summary.annualRevenueTarget || 0`；总览页由 `computeTotals` 求和 |
| 多园区大屏回款完成率 | 园区页取 `summary.annualGoalCompletion`；总览页使用 `min(100, annualRevenueCollected / annualContractReceivable * 100)`，不按园区完成率简单平均 |
| 多园区大屏出租率 | 园区页取 `summary.occupancyRate`；总览页按 `totalArea * occupancyRate` 加权汇总，不做简单平均 |
| 多园区大屏本月应收/实收/未收 | 取 `processedData.currentMonthBilling`，租金和物业费按 `feeKind` 拆分；未收为 `max(0, amountDue - amountPaid)` |
| 多园区大屏物业费 | 仅统计启用物业费应收的园区；年度实收取本年 `ManagementFee` 且 `Received` 的流水，年度应收按服务层滚动账单汇总 |
| 多园区大屏新签/退租/净增面积 | 取服务层 `newContractsArea`、`terminatedContractsArea`，净增为二者相减 |
| 多园区大屏预警 | 待收款和合同到期来自 `generateAllAlerts`；出租率偏低和回款落后来自大屏指标生成的低出租率 / 低回款预警 |
| 合同分析通用趋势图 | `Charts.tsx` 只读取传入的 `monthlyTrends` 字段，例如 `occupancyRate`、`revenueTarget`、`revenueCollected`、`collectionRate`、`avgUnitPrice`；图表组件不得二次计算口径 |
| 合同分析面积变动图 | `ContractAnalysisCharts.tsx` 只绑定传入的 `newArea`、`lostArea`、`netArea`；移动端可重排图例和图表，但不得改动数据 key |
| 合同摘要推算应收 | `ContractSummaryModal.tsx` 展示 `billPreviewState.yearBills`；账单由云端 `fetchCloudBudgetedBillsPreviewBatch` 或本地 `generateBudgetedBills` 缓存生成，UI 只展示 `date`、`amount` 和 `budgetBillCoverageLabel(b)` |
| 合同摘要当前核销账期高亮 | 由 `billAccrualMonthMatchesReceivableMonth`、`billDateMatchesReceivableMonth`、`billCoverageTouchesReceivableMonth` 判定；视觉高亮不得替代账单归属逻辑 |

## 验收清单

- 桌面 1280px 以上：侧栏不遮挡主画面，主内容有明确视觉焦点。
- 移动 390px 宽：无横向溢出，顶部、提示条、主卡片全宽可读。
- 移动端工作台：首屏应先展示“今日待办”行动卡或稳定空态，点击待办卡应进入对应查询 / 核销 / 合同入口。
- 移动端查询：合同状态 chips、已筛数量和清除按钮应可用，默认空搜索不应把已退租客户计入可见结果；无结果应使用 readable 玻璃空态，说明是筛选无结果还是真实无数据；长结果集应显示「已显示 X / 共 Y 条」，并提供「显示更多 / 收起结果」渐进查看；结果卡即使视觉截断，也必须保留完整客户名、位置、状态和收款 / 欠费摘要的 `aria-label` / `title`；结果卡点击「合同 / 核销」应带着当前客户进入对应模块并预填搜索。
- 移动模块顶部：客户查询、合同轻管理和财务待处理账款的 `liquid-mobile-hero` 必须使用浅色 readable 玻璃和深色正文；不得再用 `text-white` 作为默认标题 / 辅助说明颜色，蓝色只用于 active、主操作和状态强调。
- 移动端复杂筛选：点击“筛选”应打开 bottom sheet；楼栋、到期月份、收款记录和当前账期筛选应即时影响已筛数量和客户列表，重置后恢复全部结果；筛选面板必须保持 dialog / modal 语义、可见标题、关闭按钮、背景点击和 Escape 退出。
- 移动端当前账期筛选：筛选文案必须保持为“当前账期未收 / 当前账期无未收”，不得替换成历史欠费口径。
- 移动端历史欠费筛选：只有客户级历史欠费汇总可用时才可选择“有历史欠费 / 无历史欠费”；存在缺少 `details_json` 的封账月时必须禁用或重置历史欠费筛选，并给出原因，不得用园区 `accumulatedArrears` 或当前账期待收推断客户历史欠费。
- 旧封账明细迁移：上线前应通过 `npm run seal:backfill -- --from 2026-01 --to 上月 --dry-run` 检查旧封账覆盖；已有但缺 `details_json` 的封账月应被脚本识别为 `update_for_missing_details`，已有明细的封账月应跳过，必要时才能使用 `--force` 覆盖。
- 客户级历史欠费云端接口：移动查询进入历史欠费筛选时应优先调用 `/api/integration/app/compute/tenant-historical-arrears`；网关不可用、服务端计算关闭、token 缺失或本地存在未保存编辑时才走前端按需 fallback。物业账号仅应聚合物业费欠费，不能返回租金欠费。
- 移动端复杂面板：查询、筛选、轻管理等包含局部弹层 / 焦点 / 多组筛选的面板应拆成独立组件；`App.tsx` 只保留数据编排、权限、路由和口径状态，不应继续承载大段移动展示 JSX。
- 移动端更多入口：底部“更多”应两步内进入楼宇资管、预算管理、初始化数据和系统与备份，且进入后不得被自动重定向回工作台。
- 移动导航组件边界：`MobileNavigation` 只负责底部导航和更多入口展示，不应直接读取业务数据、切换园区或写入状态；新增移动管理入口时应在 `App.tsx` 构造回调和权限，再传给组件。

- 移动端导入结果：合同和楼宇批量导入结果弹窗必须保持 dialog / modal 语义、可见标题、命名关闭按钮、背景点击、面板点击隔离和 Escape 退出；导入汇总、失败明细、失败明细导出、楼宇合同同步行和导入写入逻辑仍必须复用现有导入口径。
- 移动端空态：合同、财务、发票等管理列表不得只显示一行浅灰字；应使用 readable 玻璃空态，说明是无数据还是筛选无结果，并在安全的场景提供下一步动作。
- 移动端数字输入：金额、单价、面积、出租率、月份等关键数字输入必须显式声明 `inputMode` 与合适的 `enterKeyHint`；运行时兜底只能防漏，新增源码字段不得只依赖兜底脚本。
- 移动端表单语义：登录 / 注册、搜索、金额、日期、面积等移动表单字段必须有明确标签关联或 `aria-label`，关键表单容器应通过 `aria-labelledby` / `aria-describedby` 关联可见标题和说明，并声明适合当前任务的 `inputMode` / `enterKeyHint`；邮箱类字段应关闭自动大写和拼写检查，避免 iOS 键盘自动修正造成登录失败。
- 移动端反馈语义：登录 / 注册、筛选、保存、导入和轻管理等移动流程的错误必须使用 `role="alert"` 或 assertive live region，成功 / 普通状态使用 `role="status"` 或 polite live region；提交、同步或导入按钮应暴露 `aria-busy`，避免用户只看到视觉 spinner。
- 移动端分组选项语义：登录 / 注册、筛选、园区多选、状态批量处理等成组选项必须有可见分组标签或 `aria-label`，加载时暴露 `aria-busy`，计数变化用 polite live region，空态 / 加载态不能只是一行静态小字。
- 移动端触控目标：底部导航、更多入口、年份切换、筛选 chip、登录 / 注册输入框、园区多选项、图标关闭按钮、楼宇轻管理 pill 和 action sheet 选项的实际命中区不得小于 44px；视觉胶囊可收窄，但手机上不能只有小图标区域可点。
- 移动端玻璃性能：底部导航、更多弹层、筛选弹层、月度明细和抽屉的移动实景 blur 不应超过 18px；复杂浮层应有绘制隔离，打开/关闭后不得造成明显卡顿或遮罩残影。
- 移动端长列表：预算、楼宇、合同、财务、发票等移动列表必须保留底部导航安全留白和内部滚动隔离；横向状态 chips、筛选 / 月份轨道、关注字段轨道应有可见的滑动提示，关注字段这类卡片组还应暴露列表 / 列表项语义，不应让最后一张卡片被固定底栏遮挡。
- 移动端首屏 QA：375×812、390×844、430×932、768×1024 首屏应无横向溢出、无框架错误覆盖；年度达成主值应优先显示当前顶栏园区的可用 KPI，不得在当前园区已有数据时只显示 `...` / `读取中`；固定底部导航不得遮挡关注字段标题、关注字段卡辅助文字或待办卡关键文字；工作台底部不得再出现园区汇总 / 切换卡；深色系统问题必须用 `--color-scheme dark` 或 `--color-scheme both` 留存证据，动效、弹层或加载状态问题必须用 `--reduced-motion reduce` 或 `--reduced-motion both` 留存证据，登录后页面必须先通过 `npm run qa:mobile-auth-state` 生成本机登录态，再用 `--storage-state` 复用登录态并追加 `--require-authenticated`；基础视口截图目录必须通过 `npm run qa:mobile-screenshot-report -- 截图报告路径`。
- 移动端源码守卫：每次改动移动工作台、底部导航、更多入口、筛选弹层、月度明细、触控命中区、自定义字段或暗色 / 玻璃材质后，应先运行 `npm run qa:mobile-ui`；守卫应继续覆盖 CSS 结构平衡、关键移动选择器和自定义字段状态文案，该命令通过后仍需按上条做真实视口截图。
- 移动字号守卫：核心移动卡片里的标签、辅助说明、顶部上下文胶囊和底部导航标签必须保持 12px 可读下限；`mobile-typography-guard` 覆盖范围内不得绕开 9/10/11px 兜底，新增移动卡片类时应同步纳入守卫或直接使用 `text-xs` 以上字号。
- 移动深色系统可读性：真机处于深色外观时，登录 / 注册页和工作台浅色玻璃卡片仍应保持深色主标题、数字和辅助文案；不得出现白字叠白玻璃、输入框占位文字过浅、底部导航未选中项过浅、今日待办卡文字发白，或主 KPI 白字直接压在高亮蓝色透明层上。

- 移动降低透明度可读性：系统开启降低透明度时，登录 / 注册页、年度达成主 KPI、三列 KPI、关注字段、今日待办、底部导航、月度明细和筛选 / 轻管理浮层应取消实时模糊并使用更实背景；不得让关键数字继续依赖透明材质辨识。
- 移动减少动态效果：系统开启减少动态效果时，移动卡片、bottom sheet、月度明细、toast、加载图标、抽屉和管理弹层应关闭滑入、缩放、淡入、旋转、跑马灯和 pulse 等动效；不得用动效替代标题、焦点、选中态或状态文案。
- 移动入场动画兜底：所有使用 `mobile-card-enter` 的工作台、关注字段、待办和轻管理卡片必须从关键帧第一帧起可见，并具备可见默认终态；减少动态或动画中断时不得停留在 `opacity: 0`、偏移或缩放的初始帧。
- 移动弹层语义：底部“更多”、筛选、轻管理 action sheet、设置弹层和明细弹层应声明 dialog / modal 语义，提供可见标题或明确标签，并支持关闭按钮、背景点击和 Escape 退出；新增浮层不应只依赖视觉遮罩表达模态状态。
- 移动选中态语义：登录 / 注册分段、底部导航、更多管理入口、状态 chips 和筛选选项必须把视觉选中同步为 `aria-current` 或 `aria-pressed`；搜索类输入必须保持 `type="search"`、明确 `aria-label` 和合适的移动完成键。
